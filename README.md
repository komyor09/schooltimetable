# Электронное расписание уроков — МТМУ №40

Веб-система для автоматизированного составления и публикации расписания уроков.
Реализована по техническому заданию `TZ_electronnoe_raspisanie.docx` (см. раздел
«Отклонение от ТЗ» ниже).

## Установка

Требуется **Node.js 22.5+** (используется встроенный модуль `node:sqlite`,
внешняя СУБД не нужна). Python и другие зависимости не требуются.

```bash
git clone https://github.com/komyor09/schooltimetable.git
cd schooltimetable
npm install        # ставит Express, EJS, HTMX, Tailwind CLI
npm run build:css  # собирает public/vendor/tailwind.css из src/styles/input.css
npm start           # поднимает сервер на http://localhost:3000
```

При первом запуске автоматически создаётся файл БД `data/schedule.db` по схеме
из `data/schema.sql` и заполняется время уроков по умолчанию. Для разработки
удобнее `npm run dev` — сервер сам перезапускается при изменении файлов в
`src/` и `locales/`.

Если менялись классы Tailwind в шаблонах (`src/views/**/*.ejs`), пересоберите
стили командой `npm run build:css` — без этого новые классы не появятся в
скомпилированном CSS.

## Использование

1. Откройте `http://localhost:3000` — попадёте на главную страницу с входами
   для завуча и зрителей.
2. **Панель завуча** (`/classes` и соседние разделы в навигации): заведите
   справочники — классы (с сеткой дней/уроков), учителей (предметы,
   методический день, занятые дни), предметы, кабинеты, затем учебный план
   (`/curriculum`) и при необходимости подгруппы (`/subgroups`).
3. Хотите быстро посмотреть систему в деле без ручного ввода — на главной
   странице есть кнопка **«Сгенерировать тестовые данные»**: заполнит все
   справочники демонстрационным набором (важно: заменяет текущие данные).
4. На странице **«Расписание (черновик)»** (`/schedule`) нажмите
   «Сгенерировать» — система построит черновик без конфликтов учителей;
   нерешённые слоты (если есть) можно доправить вручную кликом по ячейке.
5. Нажмите **«Опубликовать»** — расписание станет видно зрителям.
6. Зрители смотрят расписание на **«Публичный просмотр»** (`/public-view`,
   по классу или учителю), на **«ТВ-табло»** (`/tv` — режимы «Текущий день» и
   «Неделя с автопрокруткой» для экрана в коридоре) и распечатывают через
   **«Печать»** (`/print`).
7. Язык интерфейса (RU/TJ) переключается кнопками в правом верхнем углу.

Подробности — в `docs/USER_GUIDE.md` (полное руководство завуча) и
`docs/DEPLOYMENT.md` (установка на школьный компьютер, автозапуск, резервное
копирование).

## Стек

- **Backend:** Node.js + Express
- **Шаблоны:** EJS + express-ejs-layouts (серверный рендеринг)
- **Интерактивность:** HTMX (без отдельной сборки фронтенда)
- **Стили:** Tailwind CSS (собирается в статический файл)
- **БД:** встроенный `node:sqlite`, один файл `data/schedule.db`
- **i18n:** RU / TJ, переключение в интерфейсе

## Отклонение от ТЗ

Раздел 5.1 технического задания указывает стек Python/FastAPI. На машине, где
разрабатывалась система, Python отсутствовал, и по согласованию было решено
использовать архитектурно равноценную замену на Node.js: Express вместо FastAPI,
EJS вместо Jinja2. HTMX, Tailwind CSS, SQLite (один файл), офлайн-работа и
отсутствие сборки фронтенда сохранены в точности как в ТЗ. Функционально
система полностью соответствует всем разделам ТЗ (3.1–3.13).

## Структура проекта

```
src/
  server.js              — точка входа, настройка Express
  db.js                   — подключение node:sqlite, схема, дефолтное время уроков
  i18n.js                  — словари RU/TJ
  routes/                   — по одному файлу на раздел (классы, учителя, ...)
  services/
    scheduler.js             — движок автогенерации расписания
    conflicts.js               — проверка конфликтов учителя
    scheduleData.js             — общие запросы для публичного просмотра/ТВ/печати
  views/                        — EJS-шаблоны
data/schema.sql                 — DDL базы данных
locales/{ru,tg}.json              — словари интерфейса
docs/                              — руководство завуча, развёртывание, настройка ТВ
```

## Алгоритм автогенерации

См. `src/services/scheduler.js`. Кратко: сначала предметы жадно раскладываются по
сетке дней/уроков каждого класса (по учебному плану параллели), затем отдельно по
каждой смене подбираются учителя слот за слотом («сначала самое ограниченное» +
балансировка нагрузки, несколько случайных попыток). Слоты, которые не удалось
закрыть автоматически (например, единственный подходящий учитель занят в
единственный возможный день), не блокируют генерацию — они попадают в отчёт и
дорабатываются вручную в черновике, что и предусмотрено ТЗ (п. 3.8).
